# AGENTS.md | TRAE SOLO 开发规则

## 一、项目概述

为YUKINGS Shoptop独立站批量开发15个声屏障案例页，面向欧美B2B基建客户；**页面设计、组件、交互、HTML/CSS代码必须与网站现有产品详情页完全统一**。严格执行 RESEARCH.md、PRD.md、TECH\_DESIGN.md 全部要求。

## 二、强制红线规则（优先级最高）

1.  样式层面：所有配色、字体、卡片、按钮、表格、图标、留白，1:1复刻产品详情页，禁止自定义样式、配色、尺寸。
2.  代码层面：优先复用产品详情页现有CSS类名、HTML标签结构、JS脚本，不新增独立样式与交互代码。
3.  组件层面：表单、悬浮CTA、下载按钮、推荐卡片等全站组件，严格沿用产品页样式与交互。
4.  内容层面：数据取自Excel，全专业英文、国际单位，无中式文案。

## 三、代码规范、文件规则、输出要求（补充版，适配YUKINGS案例页批量开发）

### 3.1 代码规范（强制对齐产品详情页）

1.  **语言与技术栈**
    *   仅使用 HTML5 + 原生 CSS3 + 轻量化 JS，不引入外部大型框架（如 Vue/React）、iframe、第三方插件。
    *   所有样式优先复用产品详情页的现有 CSS 类名，禁止为案例页新增独立的全局样式。
    *   如需补充样式，仅使用内联样式或局部 `<style>` 标签扩展，且必须与产品详情页的设计系统保持一致（颜色、字体、间距、组件样式）。

2.  **HTML 结构规范**
    *   页面整体 DOM 结构、标签层级、模块包裹方式，1:1 复刻产品详情页的代码结构，如：
        *   模块使用 `<section>` 包裹
        *   数据卡片使用 `<div class="card">` 类（复用产品页类名）
        *   表格使用 `<table class="spec-table">` 类（复用产品参数表类名）
    *   图片标签必须添加 `alt` 属性，格式为 `项目名称 | 关键词 sound barrier project`，与产品详情页图片 alt 规则统一。
    *   表单结构、输入框、按钮的 HTML 写法，完全沿用产品详情页的表单组件代码。

3.  **CSS 样式规范**
    *   品牌色强制使用：`#082457`（主色）、`#E4662A`（辅助色）、`#F5F7FA`（背景）、`#333333`（正文）、`#666666`（辅助文字）。
    *   字体统一使用 `Archivo`，标题、副标题、正文的字号、行高、字间距，严格对齐产品详情页的字体层级。
    *   响应式断点（桌面/平板/手机）、媒体查询规则，直接复用产品详情页的代码，不新增自定义断点。
    *   按钮、卡片、表格、图标、悬浮CTA等所有组件的样式，100%复刻产品详情页的 hover 效果、边框、阴影、圆角。

4.  **JS 交互规范**
    *   仅使用原生 JS 实现轻量化交互（如悬浮按钮、表单提交、图片懒加载），且直接复用产品详情页的脚本代码。
    *   禁止添加动态特效、弹窗广告、多余的动画效果，保持页面简洁专业。
    *   所有下载链接、跳转链接、表单提交逻辑，与产品详情页的交互规则一致。

### 3.2 文件规则（适配 TRAE SOLO & Shoptop）

1.  **文件命名规则**
    *   每个案例页为独立的 HTML 文件，命名格式：`case-序号-项目英文缩写.html`，例如 `case-1-guangshen-highway.html`。
    *   所有文件统一存放在 `/pages/case-studies/` 目录下，对应 Shoptop 二级栏目路径。

2.  **图片文件规则**
    *   所有图片使用 WebP 格式，分辨率 1920px 宽，懒加载开启，图片命名格式：`case-序号-图片类型-描述.webp`，例如 `case-1-banner-guangshen-highway.webp`。
    *   图片尺寸、比例与产品详情页图片规格保持一致，避免图文排版错乱。

3.  **目录结构规范**

    /
    ├── RESEARCH.md
    ├── PRD.md
    ├── TECH\_DESIGN.md
    ├── AGENTS.md
    ├── /pages/
    │ └── /case-studies/
    │ ├── case-1-guangshen-highway.html
    │ ├── case-2-meiguan-expressway.html
    │ └── ...
    └── /assets/
    └── /images/
    ├── case-1-banner.webp
    └── ...

4.  3.3 输出要求
    1.  **单页面输出**
    *   每个案例页输出完整的、可直接运行的 HTML 文件，包含内联 CSS 和必要的 JS 脚本。
    *   每个页面必须包含：Meta 标题、Meta 描述、图片 ALT 文本、内嵌的 CaseStudy 结构化 JSON-LD 数据。
    1.  **批量生成输出**
    *   生成 15 个案例页时，需同步输出一份 `case-list.csv`，包含：序号、项目名称、英文页面名称、URL 短链、Meta 标题、Meta 描述、核心关键词。
    *   输出每个页面的「与产品详情页代码对标说明」，证明样式、结构、交互完全统一。
    1.  **校验标准**
    *   视觉校验：案例页的配色、字体、组件、排版与产品详情页无差异。
    *   代码校验：CSS 类名复用产品详情页，无自定义全局样式，结构与产品页一致。
    *   功能校验：下载按钮、表单、内链、悬浮 CTA 均可正常使用，响应式适配正常。
    *   合规校验：GDPR 表单勾选、隐私政策链接正常，无不合规代码。

## 四、严格禁止行为（补充新增）

1.  禁止自定义按钮样式、卡片样式、表格样式、弹窗样式。
2.  禁止修改现有媒体查询断点、响应式适配规则。
3.  禁止新增独立CSS样式表、大量自定义类名。
4.  禁止改动模块布局、标签层级，保证和产品详情页结构一致。

## 五、额外输出

完成代码后，附加「案例页与产品详情页样式/代码对标说明」，证明两者统一。
